# Password hashing adapter contract

**Stage:** implemented and mutation-checked in every build on 2026-09-12. This identity-owned adapter implements A03 of the identity
authentication contract. It is not a domain value and not a shared package: it
depends on the identity domain's NewPassword/PasswordInput values, the shared
secret wrapper, shared errors and an injected entropy capability. No HTTP, storage
or application operation exists here.

## Behavior

H01 — Write format is Argon2id version 19, m=19456 KiB, t=2, p=1, a 16-byte salt
from injected cryptographic entropy and a 32-byte tag, encoded as the PHC string
`$argon2id$v=19$m=19456,t=2,p=1$<salt>$<tag>` with unpadded standard-alphabet
base64 (PHC B64). Hash accepts only a validated NewPassword and hashes its
normalized UTF-8 bytes. The result is a redacting secret string.

H02 — Entropy failure refuses hashing with Unavailable `identity.entropy_unavailable`.
There is no fallback salt source.

H03 — Verify parses the record before allocating any Argon2 memory. The record is
accepted only when it is 1..512 bytes; has exactly five `$`-separated fields after
the leading `$`; names `argon2id`; carries `v=19`; carries exactly `m=19456,t=2,p=1`
in that order; and its salt and tag decode strictly (no padding, canonical, standard
alphabet) to exactly 16 and 32 bytes. Anything else is Internal
`identity.credential_corrupt` without running Argon2. This is the complete read
allowlist; a future parameter upgrade extends it explicitly with vectors.
NeedsRehash returns false for every record Verify accepts and the same corruption
fault for any other record.

H04 — Verify computes the tag with the record's salt and parameters and compares it
in constant time. Match and Mismatch are values, never errors. A mismatch is never
reported as a dependency or corruption failure, and a corruption failure is never
reported as a mismatch.

H05 — VerifyAbsent performs the same bounded work against the fixed dummy record in
the checked-in vectors and always reports Mismatch; the computed comparison is
discarded. It exists so an unknown login identifier costs comparable work.

H06 — Admission bounds all three operations. Limits are maxConcurrent >= 1,
maxQueued >= 0 and a positive queueWait. A caller that finds the concurrency slots
and the queue both full is refused immediately with Unavailable
`identity.hash_saturated`. A queued caller that waits longer than queueWait, or
whose own deadline passes while queued, gets Timeout `identity.hash_queue_timeout`.
Go maps context cancellation while queued to Canceled `identity.hash_canceled`;
Rust and Node express cancellation by abandoning the pending future and observe no
result. Refusals do not consume a slot.

H07 — Once admitted, the work runs to completion and its result is returned even if
the caller's deadline passes during the hash. A deadline cannot pretend an in-flight
native hash was killed. The slot is released after completion, including after a panic or thrown error. A blocking task that panics or is lost, or a poisoned internal lock, is Internal `identity.hash_failed`; it is neither a mismatch nor a corruption.

H08 — Invalid limits or a missing entropy capability are refused at construction
with Invalid `identity.hasher_configuration`.

H09 — The adapter never logs, formats or embeds password or record text in an
error; failures carry only their classification and a safe message.

H10 — The checked-in vectors (`testdata/vectors.json`: hashes, verify outcomes and
the dummy record) must pass in every build. The fixture was generated by one build
and is copied verbatim into each independent repository.

## Test seam

Real Argon2 timing cannot make queue states deterministic. A build may inject the
hashing work function privately for admission tests, so that a blocking fake holds
a slot; the production constructor does not expose it. Interoperability is proven by the fixture, not by the seam. Go sets an unexported package hook from an internal test; Rust exposes `Hasher::with_work` as `#[doc(hidden)]` plus `dummy_record()`; TypeScript exports `createHasher` from the hasher module only, not the package index.

## Native shapes

Go (`internal/identity/passwordhash`): `Limits{MaxConcurrent, MaxQueued int; QueueWait time.Duration}`;
`New(entropy io.Reader, limits Limits) (*Hasher, error)`;
`(*Hasher).Hash(ctx, domain.NewPassword) (secret.String, error)`;
`(*Hasher).Verify(ctx, domain.PasswordInput, secret.String) (Outcome, error)`;
`(*Hasher).VerifyAbsent(ctx, domain.PasswordInput) (Outcome, error)`;
`(*Hasher).NeedsRehash(secret.String) (bool, error)`; `Outcome` is `Match` or `Mismatch`.

Rust (`domains::identity::password_hash`): `Limits`, `Outcome`,
`Hasher::new(entropy: E, limits: Limits) -> Result<Hasher<E>, Failure>` with
`E: Entropy + Send`; `async fn hash(&self, &NewPassword) -> Result<SecretString, Failure>`;
`async fn verify(&self, &PasswordInput, &SecretString) -> Result<Outcome, Failure>`;
`async fn verify_absent(&self, &PasswordInput) -> Result<Outcome, Failure>`;
`fn needs_rehash(&self, &SecretString) -> Result<bool, Failure>`. CPU work runs on
the blocking pool behind a tokio semaphore; the hasher is shared by reference.

TypeScript (`modules/identity/password-hash`): `PasswordHasher.create(entropy: Entropy, limits: Limits): Result<PasswordHasher, Failure>` with `Limits{maxConcurrent, maxQueued, queueWaitMs}`;
`hash(password: NewPassword, options?: { signal?: AbortSignal }): Promise<Result<SecretString, Failure>>`;
`verify(input, record, options?)`, `verifyAbsent(input, options?)` returning
`Promise<Result<Outcome, Failure>>`; `needsRehash(record): Result<boolean, Failure>`.
Uses the Node 24 built-in `crypto.argon2`; an aborted signal while queued maps to
Canceled `identity.hash_canceled`.
