# Status check-in — 2026-09-23

**Where things stand:** n2f-nest is a domain-neutral boilerplate. Product work
(Signals) goes in a separate fork. The goal is a very secure, resilient base
that forks inherit. all 32 hardening items are met, and each met item is
pinned by a test or check ([hardening bar](notes/architecture/hardening-bar.md)).
`make ci fork-check` passes on a fresh stack in about a minute, and
`bun audit` is clean.

**Nothing is committed yet.** About 300 files have changed since `cd689e2`
(v1.0.8), and they wait for review and confirmation.

## What we did

### 1. Review and direction
- Did a four-part review of Identity, Organization, Document/Jobs/Audit and
  the shared infrastructure. The domain models were careful, but the adapter
  edges had defects: blind updates, lossy event delivery, workflows with no
  exit, and endpoints that leaked secrets or every tenant.
- Decided: the repository stays a boilerplate, and the
  [hardening bar](notes/architecture/hardening-bar.md) defines "done".

### 2. Correctness at the edges (resilience)
- **Optimistic concurrency.** Every aggregate carries a `version`, and updates
  are `WHERE version = $loaded`, so a conflicting write returns `<module>.stale_write`.
- **Precise database errors.** Unique violations map to domain failures, and
  serialization failures are retryable.
- **Same behavior in memory and PostgreSQL.** Contract specs run against both
  adapters for every module and for the event inbox.
- **Workflows always settle.** Document processing tracks runs and attempts,
  and stale outcomes are ignored. Jobs allow one open job per subject, and a
  reaper expires abandoned running jobs.

### 3. Event delivery
- Replaced the synchronous in-process bus. Each named consumer now has its own
  inbox with leases, exponential backoff, dead-lettering, requeue, quarantine
  of undecodable rows, and pruning.
- A failing consumer never fails the producer's write, and never affects
  another consumer.
- Hardened NATS JetStream: bounded retention, NAK with delay, TERM for poison
  messages. Hardened the outbox: backoff, quarantine, requeue.
- Added the `bun run events:requeue` script for operators.

### 4. Security
- Development endpoints now sit behind `N2F_DEV_ENDPOINTS`, and production
  (`N2F_ENV=production`) refuses unsafe configuration by name.
- Login rate limits apply per client, per account and per client+account.
  Every tenant controller has a per-client limit.
- Passwords use scrypt-v2 (OWASP parameters). Unknown emails get a decoy
  verification, so login timing does not reveal accounts.
- Added security headers, deny-by-default CORS, 64 KB JSON-only bodies, and
  sanitized error responses.
- Request IDs are generated by the server; client-supplied IDs are only echoed back.
- The audit trail is scoped to its organization. Lists use keyset pagination
  with cursors bound to the list they came from.
- `/metrics` requires a bearer token.
- Sessions end after 60 idle minutes (configurable). A login beyond 10
  sessions per identity revokes the oldest, and ended sessions are pruned
  after 7 days (S13, migration 8).
- Tenant-isolation suites prove no tenant can reach another tenant's data.
- **Sign-up reveals no accounts (S2).** Sign-up and resend answer `202` alike
  for new, taken and unknown emails, and the result is delivered by mail
  instead: a verification link or an "account exists" notice. Responses are
  held to a 1 s floor in production (measured 802 ms vs 802 ms). A new
  platform `Mailer` provides SMTP for production (nodemailer 10) and a
  capture mailer plus a `GET /dev/mail` mailbox for development; production
  refuses the capture mailer.

### 5. Module boundaries
- Modules are islands. Each exposes an `api.ts` (plus `commands.ts`, which only
  workflows may import) and states what it requires through `*_REQUIRES` ports.
- Bridges in `src/integration/` connect modules, and workflows coordinate
  commands across them. There are no cross-module foreign keys.
- `scripts/check-module-boundaries.ts` enforces this in lint.
- Rejected shared "contracts" packages. Deferred RPC and gRPC.
- Consumers decode events with their own decoders, and contract tests keep
  those decoders honest.

### 6. Operations
- Metrics cover delivery outcomes, inbox backlog, and outbox rows and lag.
- Shutdown drains readiness before closing.
- Migrations run under their own time budget with an advisory lock.
- Event retention is pruned on a schedule.

### 7. CI and tooling
- Added `Makefile` targets (`check`, `audit`, `ci`, `test-*`, `fork-check`,
  `mutation`), a `compose.yaml` test stack, and `scripts/e2e.sh`, which covers
  PostgreSQL and NATS restarts and graceful shutdown.
- GitHub Actions runs everything on each push, plus a weekly audit and
  mutation run. Dependabot is enabled.
- The error-boundary check also rejects `Promise.reject`, `.catch()` and
  `new Promise` in core layers.

### 8. Fork readiness
- **Migration squash.** The 26-migration history became 7 per-module baselines
  recorded in `n2f_migrations`. Existing databases are adopted after checking
  the old history's row count and final checksum; a partial history is
  refused. Proven by `test/migration-baseline.integration.spec.ts`
  ([ADR-001](notes/architecture/ADR-001-persistence-and-event-namespace.md)).
- **Signals names removed**, except where deliberate (legacy adoption, ADR, fixture).
- **Example modules are removable.** `make fork-check` deletes Document, Jobs
  and the workflow in a temporary copy and proves build, lint and the tests
  still pass. It runs in CI.
- **[FORKING.md](FORKING.md):** what to keep, how to delete the examples, how
  to rename the namespace, and a checklist for adding a module.
- **Mutation testing** (Stryker) runs weekly and fails below 90%, a threshold
  that is only ever raised. Domain tests took the score from 55.8% to 93.1%,
  every aggregate is at 91–95%, and no mutant is left uncovered. The new
  tests found that `encode` could issue a pagination cursor `decode` refused;
  that is now fixed. Adding a retry-schedule test also corrected a
  wrong "17 minutes" comment: the real wait before dead-lettering is 7 to
  13.5 minutes.
- **Flaky tests fixed.** The tenant suites now listen once instead of on every
  request. The outcome tests share one organization so they stay within the
  registration rate limit. 30 full runs in a row passed.
- **Outbox contract isolated.** The outbox and inbox contract runs in its own
  database. On the shared one, the integration suite's live worker could
  steal its fixture rows, and its failing publisher could dead-letter real events.

### Decisions for you
- **Unverified sign-ups hold their email.** Choose whether to expire unverified
  identities after a period, add a password reset flow that also verifies, or
  both.
- **Membership consent:** should an owner be able to add an existing identity
  without that identity's consent, or should it go through invitations only?
- **Durable suites in forks:** `postgres`, `persistent-e2e` and `restart` use
  document processing as their workload. Either make them domain-neutral, or
  leave each fork to repoint them (FORKING.md currently says the latter).
